What ./repo start actually runs

Six checks and steps, each one verified before the next begins.

1

Check the server

git, curl, PHP and cPanel's own command APIs are detected first. No root is used at any point — everything lives in your home folder.

git --version · command -v uapi · /usr/local/cpanel/bin/cpapi2

2

Verify your token and the repo — before touching anything

A fine-grained GitHub token (Administration: write, Contents: read) is checked against the GitHub API. Wrong token, missing repo or missing permission? You get a plain-language message before any change is made.

GET api.github.com/repos/owner/repo

3

Create the SSH deploy key through cPanel

The key pair is generated via cPanel's API so it appears in SSH Access → Manage SSH Keys. The public half is added to GitHub as a read-only deploy key, and the SSH login is tested against GitHub.

cpapi2 SSH genkey · POST /repos/.../keys · ssh -T git@github.com

4

Pick where the site lives

Default is ~/public_html/your-repo. Your branch is pre-filled from GitHub's default branch — just press Enter.

5

Clone the private repo

Cloned over SSH with your new key. Your first project gets the standard git@github.com:owner/repo.git remote — nothing tool-specific in the URL.

6

Register it in cPanel → Git Version Control

Called through cPanel's own UAPI, then confirmed by re-listing your repositories. The repo now behaves exactly like one you created by hand in the cPanel UI.

uapi VersionControl create · uapi VersionControl retrieve

Security, in plain terms

Your token is used once, then gone

It is read with hidden input, used for two API calls, and never written to disk. Delete it on GitHub right after setup — the tool even reminds you to.

The deploy key can only read one repo

Read-only, scoped to a single repository. If the server were ever compromised, there is no GitHub token sitting there to steal — just one limited key.

Keys live where cPanel expects them

Created through cPanel's own key system inside your home folder. cPanel already blocks public access to .git directories on your account.

Nothing is deleted without asking

Every uninstall step confirms first, the riskiest ones confirm twice. Removing the tool never breaks a working site.

Questions beginners actually ask

Do I need root or any special hosting plan?

No. Everything runs as your cPanel user from cPanel → Terminal. Shared hosting is exactly the target: files live in your home folder, no package installs, no system changes.

Does my repo really show up in cPanel → Git Version Control?

Yes — gitship registers it through cPanel's own UAPI (the same thing the Create form does) and then verifies the repo is listed. If your host restricts that API, the tool prints the three fields to enter by hand instead.

How do updates work after setup?

Push to GitHub, then click Update from Remote in cPanel → Git Version Control. That's cPanel's native flow. If the button ever refuses because the server tree diverged, run repo repair — then the button works again. repo deploy publishes without the click.

Is auto-deploy on push included?

No — gitship is deliberately cPanel-native: no webhooks, no cron jobs, no extra moving parts. The tool's job is to make the hard setup disappear; after that, cPanel manages everything and the tool can be deleted without any effect on your site.

Can I set up several private repos on one server?

Yes. GitHub deploy keys are one per repository, so gitship gives each project its own key and its own SSH config entry automatically.

What if the GitHub token stops working later?

Nothing breaks — the token is only needed at setup moments. If you revoke it, future setup steps ask for a new one. The ongoing connection uses the deploy key, which stays on GitHub independently.
